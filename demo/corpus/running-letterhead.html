Re: running elements in page margins

Dear Evaluator,

The two-line letterhead above this letter is written once, in the document source, and marked as a running element. The engine removes it from the body flow and paints a copy of it in the top margin of every page, which is how rich headers and logos are built in print CSS.

Because the copy is a laid-out clone of the element, its own styles (font size, colour, alignment and weight) travel with it. The page margin box only provides the place where it is drawn.

A body this long exists so that the letter runs across several pages at the corpus geometry. Each page then shows the same letterhead, and the page number of total in the footer keeps counting.

Paragraph four continues the letter with a little more text so that the page count is stable across engines. Northwind Systems builds deterministic typesetting software: identical input always yields identical output, byte for byte.

Paragraph five adds further length. The engine fragments the body across pages with orphan and widow control, repeats the running header in the margin box, and resolves the total page count in a second pass.

Paragraph six closes the main argument. Running elements remove the need to duplicate header markup, and they keep the header out of the body so that it never competes with content for space on the page.

Paragraph seven is here to carry the letter onto a third page at the small corpus geometry, where every page holds only a few lines of body text between the running header and the footer.
