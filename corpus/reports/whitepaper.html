Executive summary

Documents that a business sends to its customers must be reproducible. When a customer receives a statement in March and asks for the same statement again in June, the two copies must match, byte for byte, or the business has a compliance problem and the customer has a reason to distrust the record. This paper argues that determinism should be treated as a first-class product feature, describes the sources of non-determinism that a rendering engine must eliminate, and reports the results of a total-fit approach applied to a corpus of real documents.

Key finding. Every source of non-determinism we found was a design decision rather than an intrinsic property of rendering — a hash iteration order, a wall-clock timestamp, a random tie-break. Removing them cost nothing in output quality and everything in trust.

The determinism problem

An engine that renders the same input to different bytes on successive runs is failing a contract that most of its users never wrote down. The contract is implicit in the way documents are used: a statement is a record, a contract is evidence, an invoice is a demand. Each of these has a legal weight that depends on reproducibility.

The sources of non-determinism are few but persistent. Iteration order over an unordered map changes between runs and between builds. A creation timestamp written into the file's metadata changes every time the file is produced. A tie-break that consults a random number generator changes the layout of a page. Each of these is easy to remove once it is found, and each is easy to miss because the output looks right.

The discipline that catches them is a byte comparison between two runs on an unchanged input. The comparison is cheap, it is unambiguous, and it catches every class of defect at once, because any difference at all is a failure.

A total-fit approach

The layout algorithm is the second place where determinism can be lost. A greedy line breaker that fills each line in turn is deterministic by construction, but it produces poor spacing. A total-fit breaker that evaluates the whole paragraph at once produces better spacing, but only if its cost function is deterministic and its ties are broken by a fixed rule.

The approach described here uses a dynamic program over the paragraph, with a cost function that combines the badness of each line's spacing with a penalty for each hyphen. Where two break sequences have equal cost, the earlier one wins, which is a fixed rule and therefore deterministic. The same program runs on every paragraph, so the same input always produces the same breaks.

The quadratic cost is bounded in practice because a paragraph is short; the bound is what keeps the approach practical for a document with thousands of paragraphs.

Results and limits

Across the corpus, byte-identical output was achieved on every document after the sources of non-determinism were removed. Spacing quality improved measurably against a greedy baseline, and page counts were stable across repeated runs. The limits are honest: determinism is a property of a fixed input, a fixed engine version, and a fixed environment, and a change to any of the three may legitimately change the output.

The recommendation for a production deployment is therefore narrow and practical. Pin the engine version, record the input hash alongside the output hash, and re-render when either changes. The record is what matters, not the belief that nothing will ever change.
